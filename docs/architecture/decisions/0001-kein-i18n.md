# Verzicht auf i18n (keine Mehrsprachigkeit)

## Status

accepted

## Kontext

Die Anwendung wird für einen deutschsprachigen Fachbereich entwickelt und betrieben. Es gibt aktuell keine Anforderungen an Mehrsprachigkeit. Der Einsatz einer i18n-Lösung (z. B. vue-i18n) würde zusätzlichen Aufwand in Entwicklung, Tests, Pflege von Übersetzungsdateien und Schlüsselverwaltung sowie eine größere Build-/Bundle-Größe verursachen, ohne derzeit fachlichen Nutzen zu stiften.

## Entscheidung

Wir führen keine i18n-Bibliothek ein und entwickeln die Anwendung ausschließlich in deutscher Sprache:

- Keine Integration von vue-i18n oder ähnlichen Bibliotheken.
- UI-Texte werden direkt in den Komponenten/Views auf Deutsch gepflegt.
- Keine automatisierten Übersetzungs-Pipelines oder Schlüsselmanagement.

## Vorteile

- Geringere Komplexität in Code, Build und Tests.
- Weniger Pflegeaufwand (keine Übersetzungsdateien, kein Schlüsselmanagement).
- Kleinere Bundle-Größe und schnelleres Rendering.

## Nachteile

- Einführung weiterer Sprachen in der Zukunft erfordert Refactoring:
  - Extraktion harter Texte in Übersetzungs-Schlüssel/Dateien.
  - Einbau und Konfiguration einer i18n-Lösung.
  - Anpassung von Komponenten, Tests und ggf. Content-Strategie.
- Kein unmittelbarer Support für Nutzer in anderen Sprachen.
